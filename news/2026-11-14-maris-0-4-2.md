# Maris 0.4.2: tighter approvals

Maris makes one promise above all others: it can look at anything on your computer, but it **changes nothing without your OK**. This update closes places where that promise did not fully hold. Please update.

## How Maris decides what to ask about

When the assistant wants to run a command, Maris reads the command before anything runs. A command that only looks at things, such as listing a folder or asking git what changed, runs at once: being asked about every `dir` would make Maris tiring to use. Everything else waits until you press **Approve**.

That check has to be right every time. It is there for the moment a model gets something wrong, and for text in a web page or a file that tries to talk the model into something. A review of the check found commands that change things but looked like reading to it.

## What slipped through

On Windows:

- A list of files followed by `% Delete` deletes every file in the list, for good, past the Recycle Bin. `% Kill` and `% Stop` close programs and stop services the same way.
- `Format-Volume` formats a drive. It got through because `Format-Table`, which only lays out text, starts the same way. (Formatting needs administrator rights, so on most computers it would have failed anyway.)
- Setting a property, such as making a file read-only.
- The command inside `foreach ($x in …)` was not looked at at all.
- `sc` looked like the service tool, but in Windows PowerShell it means *Set-Content*, which writes a file.

On macOS and Linux, `rg --pre` runs a program on every file it searches, `tree -o` and `sort -o` write files, and a few options of `sort`, `file`, `ip`, `nvidia-smi` and `date` change things or start programs.

And in git, on every system: writing a diff into a file, deleting history with `reflog expire`, adding or removing a remote, changing a branch, putting your changes away with `stash push`, and pointing git at another repository.

All of these now wait for **Approve**. Each one is in Maris's tests too, so none of them can quietly come back.

## Projects you did not make yourself

The second fix is about git. A repository keeps its own settings in a hidden `.git` folder, and those settings can name programs that git then starts by itself, even when it is only asked what changed. A project you clone with git does not bring such settings along. A project unpacked from a zip file, copied from a USB stick or opened from a network share does.

So Maris now:

- runs git with its file monitor off, and without the index update that can start the repository's own scripts,
- asks before running git in a repository whose own settings name a program,
- and in Code mode skips its own quick look at the git status of such a project, and tells the assistant why.

## What you might notice

- `sc query` asks first. `sc.exe query` and `Get-Service` still run without asking.
- In a repository whose own settings use Git LFS filters or a credential helper, git commands ask first. In Code mode, **Always approve** → *"git status" in this project* lets a command run there without asking again.
