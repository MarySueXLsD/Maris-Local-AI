## Fixed

- **Commands that change things no longer pass as "only reads".** Maris runs a command without asking only when it just looks at things. Some commands that change things got through that check; they now wait for **Approve** like every other change. On Windows: `% Delete`, `% Kill` and `% Stop` after a list (they delete files for good, close programs and stop services), `Format-Volume`, setting a property such as `(Get-Item x).IsReadOnly = $true`, the command inside `foreach ($x in …)`, and `sc`, which in Windows PowerShell is *Set-Content* and writes a file. On macOS and Linux: `rg --pre`, `tree -o`, `sort -o` and `sort --compress-program`, `file -C`, `ip netns exec` and `ip -batch`, `nvidia-smi -lgc` and setting the clock with `date`. In git: `--output`, `reflog expire`, adding or removing a remote, changing a branch, `stash push`, and options that point git at another repository.
- **Git no longer starts programs that a project brings along.** A repository's own settings can name programs that git starts by itself, even for `git status`, and a project unpacked from an archive or copied from a USB stick brings those settings with it. Maris runs git with its file monitor off and without the index update that can start the repository's own scripts, asks before running git where a repository's settings name a program, and in Code mode skips its own look at such a project's git status.

## Changed

- `sc query` asks first; `sc.exe query` and `Get-Service` still run without asking.
- In a repository whose own settings use Git LFS filters or a credential helper, git commands ask first. In Code mode, **Always approve** → *"git status" in this project* covers a command there.
